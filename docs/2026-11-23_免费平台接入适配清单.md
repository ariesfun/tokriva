### 2.3 预算建议

`daily_budget` 限制的是每天 L2（流式生成）次数，L0（列模型）不计数。默认值 200 对多数免费层偏大，建议按实际限额设置：

| 端点 | 建议 `daily_budget` | 依据 | `timeout_sec` | `use_proxy` |

| Gemini | 15 | 社区实测 Flash 3.6 日限 20 次，留 5 次给手工使用 | 45 | 1 |
| 智谱 GLM | 50 | 部分免费模型仅 1 并发，测快了会 429 | 60 | 0 |
| ModelScope | 100 | 每日 2,000 次，留余量 | 45 | 0 |
| Hugging Face | 5 | 每月 0.10 美元，只够极少量 L2 | 45 | 1 |
| Cohere | 20 | 试用 Key 每月 1,000 次、20 次/分钟 | 45 | 1 |
| Cloudflare | 50 | 每日 10,000 Neurons，文本生成 300 次/分钟 | 45 | 视直连结果 |

小预算端点达到 90% 会自动降级为每轮只测 1 个模型，到顶后只跑 L0——接口不会从监控里消失，只是"测得少"。另有账号额度闸门，两道取更严。

## 6. 接入操作：字段、模板与验证

这一节给出"照着填就能跑"的细节。第 2 节给的是填好的结果，本节解释每个字段为什么这么填。

### 6.1 接入前检查清单

在改任何代码之前，先完成这四件事，避免把一个错误的 base_url 或 Key 写进配置：

1. **注册并拿到 Key**，确认控制台显示的免费层现状与第 4 节一致（不一致就以控制台为准，并回来更新本清单）。
2. **用 `GET /models` 冒烟**：拿 2.1 已核实的 base_url 加上 `/models`，带 Key 请求一次，看是否返回模型列表。这一步不消耗生成额度。
3. **确认默认模型的 ID**：以 `/models` 返回的 `id` 为准，不要照抄别处的写法——同一模型在不同平台的 ID 前缀可能不同。
4. **确认代理需求**：国际站点先直连试一次；被拦（CF 403、超时）再把 `use_proxy` 设为 `1`，并记录 `timing_scope = proxy_hop`。

### 6.3 连接参数（`ENDPOINTS`）字段怎么填

新增一个端点，要同时写两处：`hub/run.py` 的 `ENDPOINTS`（连接参数）和 `CATALOG_SEED`（门槛台账）。字段含义如下，与现有 4 个端点的写法保持一致。

| 字段 | 填什么 | 备注 |
|---|---|---|
| `provider` / `label` | 厂商名 / 端点短名 | `label` 用于 `--only` 单接口重测，要短且唯一 |
| `website` / `kind` | 官网 / 类型 | 聚合网关用 `proxy_station`，官方直连用 `serverless` |
| `base_url` | OpenAI 兼容根地址 | 用 2.1 核实值，冒烟通过再写 |
| `protocol` | `openai_chat` / `openai_responses` / `anthropic_messages` | 先按 `openai_chat` 试，本项目只实现了这三种 |
| `auth_env` | `.env` 里的变量名，如 `GROQ_API_KEY` | 只存变量名，Key 明文只进 `.env` |
| `default_model` | L2 基准测试用的模型 | 选该平台确认免费且非推理型的模型，避免 `REASONING_STARVED` |
| `free_only` | 聚合网关设 `1` | L0 只保留 `:free` 模型，避免把几百个付费模型塞进榜单 |
| `use_proxy` | `1` = 走 7890 代理 | 国际站点若直连被拦再开；开了要记 `timing_scope = proxy_hop` |
| `daily_budget` | 每日 L2 次数 | 额度小的平台（HF / Cohere / 智谱）要压低，默认 200 偏大；见 2.3 |
| `timeout_sec` | 单次请求超时 | 免费层波动大，国际站点建议 45–60 |

### 6.4 门槛台账（`CATALOG_SEED`）

每家至少补齐这些字段，值域按 `hub/db.py` 与 `hub/ledger.py` 定义：

| 字段 | 可取的值 | 本清单的用法 |
|---|---|---|
| `signup_method` | `EMAIL` / `PHONE` / `CARD` / `KYC` / `REGION_LOCKED` | 需手机号的填 `PHONE`，需国内实名的填 `KYC` |
| `free_form` | `STANDING` / `MONTHLY_CREDIT` / `ONE_TIME` / `TRIAL` / `PROMO` | 对应第 4 节的免费形态。注意 `hub/db.py` 旧注释写的是小写 `permanent/one_time/...`，已过时；现有 seed 实际用大写 `STANDING`，以第 4 节这套为准 |
| `allow_proxy` | `YES` / `NO` / `UNKNOWN` | **一律先留 `UNKNOWN`**，按禁止转发处理；人工核对条款后才 `--allow YES` |
| `source_type` | `official` / `manual` / `dataset` | 现有 seed 用小写 `official` / `manual`；官方页核实填 `official`，仅原清单记录填 `manual` |
| `confidence` | `CONFIRMED` / `LIKELY` / `POSSIBLE` / `UNKNOWN` | 与第 4 节核实结论对应 |
| `quota_scope` | `KEY` / `PROJECT` / `ORG` / `ACCOUNT` / `IP` | Gemini 填 `PROJECT`、Groq 填 `ORG`、OpenRouter 填 `ACCOUNT` |
| `quota_visibility` | `PUBLIC` / `CONSOLE_ONLY` / `UNPUBLISHED` | Gemini / Mistral 属 `CONSOLE_ONLY` |
| `requires_card` / `requires_realname` / `requires_phone` | `YES` / `NO` / `UNKNOWN` | 决定注册门槛，别漏填 |
| `note` | 自由文本 | 写清免费层的坑，例如 ModelScope 的 `choices: null` |

### 6.5 验证步骤

每接入一个端点，按这个顺序验证，确认无误再进下一批：

1. **单接口探测**：`python -m hub.run --only Groq`，跑一轮 L0 + L2，看控制台输出的状态、流式判定、TTFT/TPS 是否合理。
2. **看汇总报告**：`python -m hub.run --report`，确认新端点出现在列表里，且没有被判成 `AUTH_FAILED` / `RESPONSE_INVALID`。
3. **看台账**：`python -m hub.run --catalog`，确认门槛字段都写进去了，`allow_proxy` 仍是 `UNKNOWN`。
4. **查脱敏**：确认数据库 `request_json` / `resp_body` 里没有 Key 明文（用 `scrub.py` 的关键词 `authorization` / `x-api-key` / `cookie` 搜一遍）。
5. **跑全量测试**：`python -m unittest discover -s hub/tests -p "test_*.py"`，确认没引入回归。
6. **观察一轮**：让常驻循环跑 2–3 小时，看首页的可用率与延迟是否稳定；429 不应把端点踢出榜。

### 6.6 出问题怎么退

- **Key 错 / 鉴权失败**：先查 `.env` 变量名是否与 `auth_env` 完全一致，再确认 Key 没过期；不要把 Key 直接写进 `run.py`。
- **返回 HTML / 登录页**：判为 `RESPONSE_INVALID`，通常是 base_url 写错或需要走代理，回到 6.1 重做冒烟。
- `REASONING_STARVED`（正文为空、全是思考）：把 `default_model` 换成非推理模型，或提高 token 预算后重测。
- **TPS 显示"不可测"**：说明服务是整包缓冲，属诚实标注，不是故障；不要为了好看去编数字。
- **要整体撤回**：先停探测（接口详情里把该端点设为未启用，或调 `PUT /api/endpoints/{id}/active` 传 `active: false`），再从 `ENDPOINTS` 和 `CATALOG_SEED` 删掉该条。注意 `seed_endpoints` 是幂等 upsert，**只删代码不会删掉库里的记录**——必须显式禁用，否则下一轮还会照常探测。已下发的网关配置用 `python -m hub.run --rollback` 回滚。

## 7. 接入后必须遵守的项目口径

这些是本项目已定死的规则，新增端点时不能破例：

- **密钥不出库**：Key 明文只写根目录 `.env`，代码里只写变量名；日志与 `request_json` 入库前脱敏 `authorization` / `x-api-key` / `cookie`。
- **下发有安全门**：新端点的 `allow_proxy` 默认是 `UNKNOWN`（按禁止转发处理）。即使探测结果很好，也不能自动下发到 LiteLLM 网关，必须先人工核对条款再 `--allow YES`。
- **429 不算故障**：瞬时限流不进可用率分母，也不因此把端点踢出榜——Gemini / Groq / ModelScope 都会频繁 429，这条尤其重要。
- **额度小的端点压低预算**：`daily_budget` 控制每日 L2 次数，到 90% 先降级、到顶只跑 L0；另有账号额度闸门，两者取更严。
- **TPS 不可测要诚实**：整包缓冲的服务标 `tps_unreliable`，不给假数字；探测 prompt 要能产生多 token 输出（默认 `Count from 1 to 20.`）。
- **模型名展示**：优先用 `model.display_name`，原始 `model_id` 作小字副标题，未知信息标 `—`。
- **排名单一来源**：前端、接口、下发都调 `hub/rank.py`，新增端点不要另写打分逻辑。
